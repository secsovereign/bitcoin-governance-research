## Methodology

**Review Counting**: Quality-weighted (GitHub, ACK, IRC, combined mailing lists, Delving, Bitcointalk), MAX per reviewer  
**PR Classification**: Multi-criteria (file changes, file types, keywords, labels)

### Importance Levels

1. **TRIVIAL**: Typo fixes, formatting, trivial changes
2. **LOW**: Documentation, tests, housekeeping
3. **NORMAL**: Regular code changes
4. **HIGH**: Significant features, refactoring
5. **CRITICAL**: Consensus / security / protocol (or large + consensus-tagged)

---

## The Question

**"A lot of PRs that get merged are housekeeping type things that arguably don't need much if any review. Are we accounting for that?"**

Zero-review rates fall as importance rises, but they do **not** go to zero on critical work.
