# Discourse recall

**Date:** 2026-10-10
**Machine-readable:** `findings/data/discourse_recall.json`
**Problem:** How many pull requests gain an observed discussion when a message that names a file the pull request touches, inside the open window plus 14 days, is counted as well as a message that names the pull request number.

The pass 6 rule, set before this scan, is this. Hand-label 200 path-only candidate links. If precision is below 0.7, number matching stays the headline and path linking is a sensitivity check.

## Result

Precision on the 200 labeled candidates is 0.015 (3 true of 200). Number matching remains the headline.

Path links touch 5968 pull requests. 576 of those had no number link. That is 0.0229 of 25122 pull requests. The candidate population was 36620 path-only hits. Number links already reach 19572 pull requests.

## Family

The path-link reruns are not entered in the Benjamini-Hochberg family, because precision is below 0.7. The existing family is 228 tests. No prior test moved across q=0.05.

Symbols the pull request touches are DATA UNAVAILABLE on the bulk scan. The enriched pull requests store filenames, not patch text.

find_discourse is available. Its hits mix GitHub pull-request text with IRC lines that are already in messages.jsonl. GitHub file lists are not discourse, so the scan uses the local IRC, mail, Delving, and Bitcointalk archives.

## What this cannot prove

- A path mention is not proof the speaker had this pull request in mind.
- Symbols in the patch are not in the enriched file, so symbol linking was not applied to the bulk scan.
- Precision below 0.7 keeps number matching as the headline. The path linker is then a sensitivity check.
- Linking discussion does not show that the discussion changed the decision.
